WebGL2D API 文件

以 WebGL 實作、與 CanvasRenderingContext2D 介面相同的 2D 繪圖函式庫。每個 API 都附有可直接編輯、執行的範例，並和原生 Canvas 2D 並排對照。

概覽

  • 介面一致：方法名稱、參數、多載、屬性預設值與驗證規則都依照 HTML Canvas 2D 規格。
  • WebGL 2 優先：預設建立 WebGL 2 context，不支援時退回 WebGL 1。
  • 零相依：單一 webgl2d.js（UMD），可用 <script>、CommonJS 或 bundler 載入。
<script src="webgl2d.js"></script>
<script>
  const ctx = WebGL2D.getContext(canvas);   // 取代 canvas.getContext('2d')
  ctx.fillStyle = 'tomato';
  ctx.fillRect(10, 10, 100, 50);
</script>
一個 <canvas> 只能有一種 context。已經呼叫過 getContext('2d') 的 canvas 無法再建立 WebGL2D，反之亦然。

範例怎麼用

  • 標示「WebGL2D 專屬」的範例（例如自訂 shader 濾鏡）沒有原生版本可以對照。
  • 每個範例的程式碼都可以直接編輯。停止輸入約半秒後會自動重新執行，也可以按 執行 或 ⌘/Ctrl + Enter。還原 會回到原始範例。
  • 左邊的畫布是 WebGL2D 的結果，右邊是同一段程式在 原生 Canvas 2D 上的結果（可在側欄關閉）。畫布大小為 320 × 200。
  • 範例中可以使用的變數： ctx（context）、canvas、Path2D（WebGL2D 端為 WebGL2D.Path2D）、WebGL2D、 log(...)（輸出到範例下方）、sampleImage（160×100 的示範圖片）、tile（20×20 的圖樣磚）。
  • 每次執行前，context 都會先 reset()，所以範例之間不會互相影響。範例程式可以使用 await（例如等待影片開始播放）。
  • 範例依你的螢幕以 devicePixelRatio 倍解析度渲染（見讓畫面更清晰）。原生對照端也套用了同樣的縮放，所以 setTransform 等方法在兩邊的行為一致。

實作原理

功能 做法
路徑 點在加入路徑時，就用當下的變換矩陣轉成裝置座標。Bézier 曲線依 Wang's formula 攤平，弧與橢圓依半徑與縮放量決定分段數，誤差約 0.2 px。
填滿 Stencil-then-Cover：先把三角扇寫進 stencil 計算環繞數（nonzero 用 INCR_WRAP/DECR_WRAP，evenodd 用 INVERT），再畫外接矩形上色並清除 stencil。
描邊 先轉回使用者座標，在 CPU 上產生線段、接合、端點與虛線的三角形，再透過 stencil 去除重疊，半透明線條交疊處不會變深。
裁切 stencil 最高位元 0x80 當裁切遮罩，低 7 位元給填色計算，巢狀 clip() 自動取交集。
上色 單一 shader，支援純色、線性／放射（完整雙圓錐公式）／圓錐漸層、圖樣、影像與文字遮罩。
合成 Porter-Duff 運算以預乘 alpha 對應 blendFunc，無界運算會額外把形狀以外清成透明。混合模式（multiply、overlay、hue……）需要讀取目的地顏色：先把圖形畫進離屏圖層，再複製目的地區域，由混合 shader 依 W3C Compositing 規格計算。
文字 由離屏 2D canvas 依目前的縮放倍率把字形點陣化成 alpha 遮罩，再由 WebGL 以任意樣式上色。
濾鏡 / 陰影 繪圖先畫進離屏圖層（WebGL 2 為 MSAA），再執行 shader pass：可分離高斯模糊、色彩矩陣、陰影上色與疊合、自訂 GLSL。每個 pass 都用 scissor 限制在圖形外框加上擴散範圍內。

讓畫面更清晰

畫面模糊最常見的原因是高解析度螢幕：Retina 螢幕的 devicePixelRatio 是 2（甚至 3）。如果 canvas 的 width/height（backing store）等於 CSS 尺寸，瀏覽器就得把每個像素放大成 2×2 顯示，線條與文字就會糊掉。

做法 說明
1. 使用 pixelRatio（建議） 讓 backing store = CSS 尺寸 × dpr，並告訴 WebGL2D 這個比例。繪圖座標仍是 CSS 像素，函式庫內部以實體像素渲染；曲線分段、圓角與文字的點陣化解析度也會跟著提高。和原生的 ctx.scale(dpr, dpr) 寫法不同，setTransform、resetTransform、reset 不會把縮放清掉，isPointInPath 也可以直接使用 CSS 座標（例如 event.offsetX）。
2. 保持 MSAA 反鋸齒 antialias 預設為 true，請不要關閉。
3. 細線對齊像素 和原生 Canvas 一樣，在整數座標畫奇數寬度的線（例如 1px），線會跨在兩個像素之間而變淡。可以把座標加 0.5（moveTo(10.5, 0)），或在 pixelRatio ≥ 2 時直接忽略這個問題。
4. 像素風格的影像 放大點陣圖時設定 imageSmoothingEnabled = false；若 canvas 本身被 CSS 放大，可以再加上 CSS image-rendering: pixelated。
5. 視窗大小改變時 重新設定 backing store 尺寸（或重新呼叫 getContextHiDPI）並重畫。把視窗拖到不同 dpr 的螢幕時，也要重新設定。 
// 最簡單：一行建立高解析度 context（CSS 尺寸 400×300）
const ctx = WebGL2D.getContextHiDPI(canvas, { width: 400, height: 300 });

// 等同於：
const dpr = window.devicePixelRatio || 1;
canvas.style.width = '400px';  canvas.style.height = '300px';
canvas.width = 400 * dpr;      canvas.height = 300 * dpr;
const ctx2 = WebGL2D.getContext(canvas, { pixelRatio: dpr });

// 之後一律以 CSS 像素繪圖
ctx.fillRect(10, 10, 100, 50);
getImageData / putImageData / createImageData 是直接操作 backing store，座標與尺寸都以實體像素為單位（與原生 Canvas 相同）。pixelRatio = 2 時，CSS 座標 (x, y) 對應到像素 (2x, 2y)。

建立 Context

WebGL2D.getContext(canvas, options?) → WebGL2DRenderingContext

取得（或建立）canvas 的 WebGL2D context。同一個 canvas 重複呼叫會回傳同一個物件。

options 預設 說明
alpha true 畫布是否有透明通道
antialias true MSAA 反鋸齒
pixelRatio 1 每個繪圖座標單位對應的實體像素數；'auto' 使用 devicePixelRatio。canvas 的 backing store 尺寸要自己設定，或改用 getContextHiDPI
webgl2 true false 時強制使用 WebGL 1
preserveDrawingBuffer true 保留畫面內容（Canvas 2D 語意）；false 較快，但每格都必須整個重畫
desynchronized / powerPreference false / 'default' 直接傳給 WebGL
WebGL2D.getContextHiDPI(canvas, options?) → WebGL2DRenderingContext

建立高解析度 context 的捷徑：把 canvas 的 backing store 設為 CSS 尺寸 × devicePixelRatio，設定 canvas.style 的寬高，並啟用對應的 pixelRatio。options.width/height 是 CSS 尺寸（預設為 canvas 目前的 width/height）；options.pixelRatio 可以覆寫 dpr；setStyle: false 則不更動 CSS。其他選項與 getContext 相同。

ctx.pixelRatio number = 1

每個繪圖座標單位對應的實體像素數。設為 devicePixelRatio 並把 backing store 放大同樣倍數，就能在高解析度螢幕上得到清晰的線條與文字。路徑、變換、isPointInPath 都使用 CSS 座標；像素操作 API 使用實體像素。

WebGL2D.install() → void

修補 HTMLCanvasElement.prototype.getContext，之後 canvas.getContext('webgl-2d', options) 會回傳 WebGL2D context；其他類型照常交給原生實作。

new WebGL2D.WebGL2DRenderingContext(canvas, options?)

直接建構，不經過快取，每次都會建立新的 WebGL context。一般請使用 getContext。

ctx.canvas · ctx.gl · ctx.isWebGL2

canvas：所屬的 canvas 元素。gl：底層的 WebGL context（進階用途；必須保留 stencil 內容）。isWebGL2：是否使用 WebGL 2。

狀態

save() → void

把目前的繪圖狀態推入堆疊，包含變換矩陣、裁切區域，以及所有樣式、線條、文字、合成與陰影屬性。目前路徑不屬於狀態。

restore() → void

從堆疊彈出並還原狀態（包括裁切區域）；堆疊為空時不做事。

reset() → void

清空畫布、狀態堆疊與目前路徑，所有屬性回到預設值。

isContextLost() → boolean

WebGL context 是否已遺失（例如 GPU 重設）。遺失後不會自動恢復。

getContextAttributes() → object

回傳 { alpha, colorSpace, desynchronized, willReadFrequently }。

變換

矩陣格式為 [a, b, c, d, e, f]：x' = a·x + c·y + e、y' = b·x + d·y + f。scale、rotate、translate、transform 都會把新矩陣乘到目前矩陣上（新變換先作用在座標上）。參數含 NaN 或 Infinity 時會被忽略。

scale(x, y)

縮放座標系統。位置、大小與線寬都會一起縮放。

rotate(angle)

以目前原點為中心，順時針旋轉 angle 弧度。

translate(x, y)

移動原點。

transform(a, b, c, d, e, f)

乘上任意仿射矩陣，可以做出斜切等效果。

setTransform(a, b, c, d, e, f) · setTransform(matrix?)

直接取代目前矩陣。matrix 可以是 DOMMatrix、{a,b,c,d,e,f}、{m11,…,m42}；省略時重設為單位矩陣。

getTransform() → DOMMatrix

回傳目前矩陣的副本。

resetTransform()

重設為單位矩陣，等同 setTransform(1, 0, 0, 1, 0, 0)。

填色與描邊樣式

fillStyle string | CanvasGradient | CanvasPattern = '#000000'

填色樣式。接受任何 CSS 顏色字串：hex、rgb()、hsl()、具名顏色……無效的值會被忽略。讀取時會正規化成 #rrggbb 或 rgba(r, g, b, a)。

strokeStyle string | CanvasGradient | CanvasPattern = '#000000'

描邊（stroke、strokeRect、strokeText）使用的樣式，規則與 fillStyle 相同。

createLinearGradient(x0, y0, x1, y1) → CanvasGradient

從 (x0, y0) 到 (x1, y1) 的線性漸層。座標屬於繪製當下的使用者空間；兩點相同時不繪製。

createRadialGradient(x0, y0, r0, x1, y1, r1) → CanvasGradient

兩個圓之間的放射漸層，完整實作雙圓錐公式（兩圓可以不同心）。半徑為負時拋出 IndexSizeError。

createConicGradient(startAngle, x, y) → CanvasGradient

以 (x, y) 為中心的圓錐（角度）漸層，從 startAngle（弧度，0 為正 x 軸）開始順時針繞一圈。

createPattern(image, repetition) → CanvasPattern | null

repetition：'repeat'（預設）、'repeat-x'、'repeat-y'、'no-repeat'。建立時會擷取影像當下的內容；影像尚未載入時回傳 null。

CanvasGradient.addColorStop(offset, color)

加入色標。offset 不在 [0, 1] 時拋出 IndexSizeError，顏色無效時拋出 SyntaxError。offset 相同的色標依加入順序排列，可以做出硬邊。

CanvasPattern.setTransform(matrix?)

設定圖樣自身的變換（在 context 的變換之前套用）。

線條樣式

lineWidth number = 1

線寬，單位是使用者空間（會隨變換縮放）。≤ 0 或非有限值會被忽略。

lineCap 'butt' | 'round' | 'square' = 'butt'

線段端點的形狀。紅色參考線是路徑實際的起點與終點。

lineJoin 'miter' | 'round' | 'bevel' = 'miter'

兩條線段相接處的形狀。

miterLimit number = 10

lineJoin = 'miter' 時，若斜接長度除以半線寬超過此值，該接合會改用 bevel。

setLineDash(segments)

設定虛線樣式（實線長、間隔長交替）。數量為奇數時會自動重複一次；含負數或非有限值時整個呼叫被忽略；傳入 [] 恢復實線。

getLineDash() → number[]

回傳目前虛線樣式的副本。

lineDashOffset number = 0

虛線樣式的起始偏移量。在動畫中遞增它，就能做出「行進的螞蟻」效果。

合成

globalAlpha number = 1

套用到所有繪圖（含影像與文字）的透明度，範圍 0–1，超出範圍的值會被忽略。

globalCompositeOperation string = 'source-over'

新圖形（來源）與畫布既有內容（目的地）的合成方式，支援規格中的全部 26 個值，且都是精確計算。無效的值會被忽略。

類別 值 實作方式
Porter-Duff source-over source-in source-out source-atop destination-over destination-in destination-out destination-atop lighter copy xor 以預乘 alpha 的 blendFunc 直接合成。source-in、source-out、destination-in、destination-atop、copy 屬於「無界」運算，會依規格把圖形以外（裁切區內）清成透明
可分離混合模式 multiply screen overlay darken lighten color-dodge color-burn hard-light soft-light difference exclusion 先把圖形畫進離屏圖層，再複製目的地區域，由混合 shader 依 W3C Compositing 規格計算：Cr = (1−αb)·Cs + (1−αs)·Cb + αs·αb·B(cs, cb)，最後以 source-over 合成。screen 可以用 blendFunc 精確表達，所以直接合成
不可分離混合模式 hue saturation color luminosity
globalCompositeOperation：混合模式

混合模式會依目的地顏色調整來源顏色，常用於調色、光影與疊圖。下面的範例以圖片為目的地、彩虹漸層為來源，最後一格是一般的 source-over，可以當作對照。混合模式同樣受裁切、globalAlpha、filter 與陰影影響。

矩形

這三個方法都不會影響目前路徑。

fillRect(x, y, w, h)

以 fillStyle 填滿矩形。受變換、裁切、透明度與合成運算影響。寬高為負數時往反方向延伸。

strokeRect(x, y, w, h)

以 strokeStyle 與目前的線條樣式描邊矩形。寬或高為 0 時描成一條線。

clearRect(x, y, w, h)

把區域內的像素設為透明。受變換與裁切影響，不受透明度與合成運算影響。

路徑

下列方法也存在於 Path2D。在 context 上呼叫時，點會用當下的變換矩陣轉換；參數不是有限數值時，呼叫會被忽略。

beginPath()

清空目前路徑，開始一條新路徑。

closePath()

從目前點畫直線回子路徑的起點，讓最後一個角也有正確的接合。

moveTo(x, y)

以 (x, y) 開始新的子路徑，不畫線。

lineTo(x, y)

從目前點畫直線到 (x, y)。還沒有子路徑時等同 moveTo。

quadraticCurveTo(cpx, cpy, x, y)

二次 Bézier 曲線，只有一個控制點（紅點）。

bezierCurveTo(cp1x, cp1y, cp2x, cp2y, x, y)

三次 Bézier 曲線，有兩個控制點。

arc(x, y, radius, startAngle, endAngle, counterclockwise = false)

圓弧。已有子路徑時，會先畫直線到弧的起點。角度差 ≥ 2π 時畫整圓。半徑為負時拋出 IndexSizeError。

arcTo(x1, y1, x2, y2, radius)

畫出同時與「目前點→(x1,y1)」及「(x1,y1)→(x2,y2)」相切的圓弧，常用來畫圓角。三點共線或半徑為 0 時，退化成 lineTo(x1, y1)。

ellipse(x, y, radiusX, radiusY, rotation, startAngle, endAngle, counterclockwise = false)

橢圓弧，rotation 是橢圓本身的旋轉角（弧度）。

rect(x, y, w, h)

在目前路徑加入一個封閉的矩形子路徑。

roundRect(x, y, w, h, radii = 0)

圓角矩形。radii 可以是數字、{x, y}（橢圓角），或含 1–4 個值的陣列，對應方式與 CSS border-radius 相同。半徑太大時會等比縮小。

填滿 / 描邊 / 裁切

path 參數必須是 WebGL2D.Path2D。fillRule 為 'nonzero'（預設）或 'evenodd'。

fill(fillRule?) · fill(path, fillRule?)

以 fillStyle 填滿目前路徑或指定的 Path2D。未封閉的子路徑會自動視為封閉。

stroke() · stroke(path)

以 strokeStyle 描邊。線寬依呼叫當下的變換計算，自身交疊的部分只上色一次。

clip(fillRule?) · clip(path, fillRule?)

把裁切區域設為「目前裁切區 ∩ 路徑」，之後的繪圖只會出現在裡面。用 save()/restore() 還原。

isPointInPath(x, y, fillRule?) · isPointInPath(path, x, y, fillRule?) → boolean

判斷畫布座標（不受變換影響）中的點是否在路徑內。可以用來做點擊偵測。

isPointInStroke(x, y) · isPointInStroke(path, x, y) → boolean

判斷點是否落在描邊範圍內，會考慮線寬、端點、接合與虛線。

文字

fillText(text, x, y, maxWidth?)

填色繪製文字，可以使用漸層與圖樣。指定 maxWidth 且文字較寬時，會水平壓縮以符合寬度。

strokeText(text, x, y, maxWidth?)

描邊繪製文字，使用目前的線寬、接合與虛線設定。

measureText(text) → TextMetrics

回傳瀏覽器原生的 TextMetrics（width、actualBoundingBox*、fontBoundingBox*……）。

font string = '10px sans-serif'

CSS font 簡寫。無效的值會被忽略；讀取時回傳正規化後的字串。

textAlign 'start' | 'end' | 'left' | 'right' | 'center' = 'start'

文字相對於 x 座標（紅線）的水平對齊方式。

textBaseline 'top' | 'hanging' | 'middle' | 'alphabetic' | 'ideographic' | 'bottom' = 'alphabetic'

文字相對於 y 座標（紅線）的垂直對齊方式。

direction 'ltr' | 'rtl' | 'inherit' = 'inherit'

文字方向，會影響 textAlign 的 start / end。inherit 視為 ltr。

letterSpacing string = '0px'

字元間距（CSS 長度）。

wordSpacing string = '0px'

單字間距（CSS 長度）。

fontKerning 'auto' | 'normal' | 'none' = 'auto'

是否使用字型內建的字距調整。在「AV」「To」這類字母組合上最明顯。

fontStretch 'ultra-condensed' … 'normal' … 'ultra-expanded' = 'normal'

字寬。字型本身要有對應的寬度變體才看得出差異。

fontVariantCaps 'normal' | 'small-caps' | 'all-small-caps' | … = 'normal'

大小寫字形變體。

textRendering 'auto' | 'optimizeSpeed' | 'optimizeLegibility' | 'geometricPrecision' = 'auto'

文字繪製的取捨提示（例如連字、字距）。

影像

drawImage(image, dx, dy) · drawImage(image, dx, dy, dw, dh) · drawImage(image, sx, sy, sw, sh, dx, dy, dw, dh)

可以繪製下列來源。來源矩形超出影像範圍時，目標矩形會依規格等比裁切。

來源 影像大小（sx/sy/sw/sh 的單位） 說明
圖片：HTMLImageElement、SVGImageElement、ImageBitmap 原始尺寸 紋理會快取；尚未載入完成時不畫
WebGL2D context（另一個或自己） CSS 尺寸（canvas.width ÷ pixelRatio） 保留實體像素解析度，高解析度的 context 畫上去依然清晰。每次呼叫都會讀取最新內容
其他 context：CanvasRenderingContext2D、OffscreenCanvasRenderingContext2D、WebGL context backing store 尺寸 等同傳入它的 canvas
canvas：HTMLCanvasElement、OffscreenCanvas backing store 尺寸 每次呼叫都會讀取最新內容
影片：HTMLVideoElement、VideoFrame videoWidth × videoHeight 繪製目前的影格；readyState < 2（還沒有影格）時不畫。要播放影片，請在 requestAnimationFrame 中每格呼叫一次

createPattern 和自訂濾鏡的 sampler2D uniform 也接受上述所有來源。

drawImage(context, …)：把另一個 context 畫上來

第 2 個 WebGL2D context 可以直接傳給 drawImage，常用於離屏圖層、快取複雜圖形或合成多個畫面。影像大小以第 2 個 context 的 CSS 尺寸計算，所以 pixelRatio 不同也能正確對齊；也可以用 createPattern(context) 把它當成圖樣。

drawImage(video, …)：繪製影片

傳入 <video> 會畫出目前的影格。這個範例用 canvas.captureStream() 即時產生一段影片，所以不需要額外的影片檔；實務上用 <video src="movie.mp4"> 也是同樣的寫法。要讓畫面跟著影片播放，請在 requestAnimationFrame 中每格重新呼叫 drawImage。

drawImage(videoFrame, …)：繪製 VideoFrame

WebCodecs 的 VideoFrame 也可以直接繪製，例如來自 VideoDecoder、MediaStreamTrackProcessor，或像這個範例一樣從 canvas 建立。影像大小為 displayWidth × displayHeight。用完請呼叫 frame.close() 釋放記憶體。

imageSmoothingEnabled boolean = true

false 時使用最近鄰取樣（像素風格），同時影響 drawImage 與圖樣。

imageSmoothingQuality 'low' | 'medium' | 'high' = 'low'

影像縮放時的取樣品質，作用在 drawImage 和圖樣上；imageSmoothingEnabled = false 時不起作用。每個像素在來源影像上涵蓋的範圍（footprint）由 CPU 依「變換 × 縮放 × pixelRatio」算出，所以旋轉、斜切也能正確處理。重複圖樣的每個取樣點會各自折返，不會出現接縫。

值 縮小 放大
'low' 雙線性，單一取樣點（縮小很多時會出現疊紋） 雙線性
'medium' 在 footprint 內做 box 超取樣，效果相當於 mipmap 雙線性
'high' Mitchell 濾波超取樣（半徑 2 個輸出像素），兼顧銳利與抗鋸齒 Mitchell–Netravali 雙三次插值（B = C = ⅓）

規格把這個屬性定義為給瀏覽器的品質偏好，各瀏覽器的實際演算法不同。在無頭 Chrome（SwiftShader）中實測：low 的所有情況，以及 high 的放大，都和原生結果逐像素一致；原生 Chrome 在這個環境下縮小時不會額外濾波，WebGL2D 的 medium/high 則會確實抗鋸齒。縮小倍率超過約 16 倍（medium）或 6 倍（high）時，取樣點數已達上限，會逐漸退化。

imageSmoothingQuality：旋轉的圖樣

圖樣同樣套用取樣品質。這個例子把圖樣縮小並旋轉，low 會出現明顯的疊紋。

像素操作

createImageData(sw, sh) · createImageData(imageData) → ImageData

建立全透明的 ImageData；傳入既有的 ImageData 時，建立同尺寸的新物件。尺寸以實體像素為單位，所以範例會乘上 pr（pixelRatio）。

getImageData(sx, sy, sw, sh) → ImageData

讀回非預乘 alpha 的 RGBA 像素，超出畫布的部分為透明黑。這個呼叫會讓 CPU 等待 GPU，請避免在動畫迴圈中頻繁使用。

putImageData(imageData, dx, dy, dirtyX?, dirtyY?, dirtyW?, dirtyH?)

直接取代像素：不受變換、裁切、透明度與合成運算影響。可以用 dirty 矩形只寫入一部分。

濾鏡與陰影

設定 filter 或陰影後，每次繪圖（fill、stroke、fillRect、strokeRect、fillText、strokeText、drawImage）都會先畫進離屏圖層，接著依序執行濾鏡的 shader pass，最後依裁切、globalAlpha 與合成模式貼回畫布。處理範圍只限於圖形外框加上模糊和陰影擴散的區域。濾鏡的長度（blur、drop-shadow、shadowBlur、shadowOffset）都以 CSS 像素計算，不受變換影響，也不會因 dpr 不同而改變外觀。

filter string | ShaderFilter | Array = 'none'

CSS 濾鏡字串，可以串接多個函式依序套用：blur()、brightness()、contrast()、grayscale()、sepia()、saturate()、hue-rotate()、invert()、opacity()、drop-shadow()。也可以設定 ShaderFilter，或是字串與 ShaderFilter 混合的陣列。無效的值會被忽略；不支援 url()。

shadowColor · shadowBlur · shadowOffsetX · shadowOffsetY

陰影。shadowColor 預設為透明，只有在顏色不透明，且 shadowBlur 或位移不為 0 時才會畫出陰影。依規格，模糊的標準差為 shadowBlur / 2；陰影會在 filter 之後套用，並乘上 globalAlpha。

createShaderFilter(source, uniforms?) → ShaderFilter

用 GLSL（ES 1.00）撰寫自訂濾鏡。source 必須定義 vec4 effect(vec2 uv)，並回傳預乘 alpha 的顏色。uv 是 0–1 的紋理座標，y 軸向上。編譯失敗時會拋出 SyntaxError，訊息附有 shader 的錯誤記錄，行號對應你的原始碼。可以直接使用下列內建項目：

名稱 說明
vec4 texel(vec2 uv) 讀取輸入影像（預乘 alpha）；等同 texture2D(u_src, uv)
vec2 toCSS(vec2 uv) / vec2 fromCSS(vec2 p) uv 與 CSS 像素座標（左上為原點、y 向下）互相轉換
vec4 unpremultiply(vec4) / vec4 premultiply(vec4) 預乘 alpha 轉換
u_src · u_resolution · u_size · u_pixelRatio 輸入紋理、實體像素尺寸、CSS 像素尺寸、pixelRatio
ShaderFilter.setUniform(name, value) → ShaderFilter

設定 uniform 的值，下一次繪圖時生效。會依 shader 中宣告的型別自動選擇對應的設定方式。value 可以是數字或陣列（float、vec*、int、mat*）、布林值、CSS 顏色字串（vec3/vec4，數值範圍 0–1），或影像來源（sampler2D）。也可以在 createShaderFilter 的第二個參數一次給定。uniformNames 會列出可設定的 uniform。

uniform 型別：顏色字串與影像紋理

vec3/vec4 的 uniform 可以直接傳入 CSS 顏色；sampler2D 可以傳入任何 drawImage 接受的影像來源。紋理的方向與 u_src 相同，也就是 y 向上，影像頂端在 v = 1。

filter = [ ...字串或 ShaderFilter ]

陣列中的濾鏡依序套用，可以混合 CSS 濾鏡與自訂 shader。

applyFilter(filter, x?, y?, w?, h?)

對畫布上已經畫好的內容做後製，例如整張畫面的暗角、調色或模糊。filter 的格式與 ctx.filter 相同。矩形以 CSS 像素計算，不受變換影響、受裁切影響，省略時處理整個畫布。濾鏡格式無效時拋出 TypeError。

ShaderFilter.dispose()

釋放 shader program 與紋理。濾鏡用完後，特別是大量動態建立時，請記得呼叫。釋放後就不能再使用。

其他

drawFocusIfNeeded(element) · scrollPathIntoView() no-op

為了相容而保留，呼叫後不做任何事。（目前的瀏覽器原生並未實作 scrollPathIntoView。）

Path2D

WebGL2D.Path2D 只記錄指令，在 fill / stroke / clip 時才以當下的變換展開，所以同一個 Path2D 可以畫在不同位置。它不會覆蓋全域的 window.Path2D。

new Path2D() · new Path2D(path) · new Path2D(svgPathData)

建立空路徑、複製另一個 Path2D，或解析 SVG path data（M L H V C S Q T A Z，大小寫皆可；遇到語法錯誤時保留錯誤之前的部分）。

path.addPath(otherPath, transform?)

把另一個 Path2D 的副本加入這條路徑，可以同時套用 DOMMatrix2DInit 變換。

path.moveTo / lineTo / closePath / quadraticCurveTo / bezierCurveTo / arc / arcTo / ellipse / rect / roundRect

與 context 上的路徑方法相同，只是記錄在 Path2D 裡。

限制與差異

  • 濾鏡與陰影的成本：每次繪圖都會多做 3–8 次離屏 pass（只限圖形範圍），大量小圖形同時套用濾鏡時，可以考慮先畫完再用 applyFilter 一次處理。filter 不支援 url()。自訂 shader 與無界合成模式會處理整個畫布。
  • 濾鏡長度與 dpr：WebGL2D 的 blur、陰影等長度以 CSS 像素計算；原生 Canvas 以 backing store 像素計算，所以原生用 scale(dpr) 做高解析度時，模糊會變成一半。（本文件的原生對照已經補正這一點。）
  • Path2D：fill、stroke、clip、isPointIn* 只接受 WebGL2D.Path2D。
  • 改變 canvas 尺寸：原生 2D 會重設所有狀態；WebGL2D 只會更新 viewport 與裁切遮罩，其他狀態保留。需要完全重設時請呼叫 reset()。
  • 反鋸齒依賴 WebGL 的 MSAA，邊緣和原生 2D 略有不同（平均每像素差異約 0.1–2，範圍 0–255）。
  • 文字：字形由離屏 2D canvas 點陣化成遮罩；單一字串的遮罩最大 4096 px，超過時會降低解析度。
  • 漸層的色標會烘焙成 512 階的紋理，極窄的硬邊可能會有 1 階的柔化。
  • stencil 環繞計數只有 7 個位元，同一點被超過 127 層同向的子路徑覆蓋時，nonzero 判斷可能出錯。
  • WebGL context 遺失後不會自動恢復。

效能建議

  • 重複出現的形狀做成 Path2D，再搭配 setTransform 重複使用。
  • fillRect、drawImage、文字是凸四邊形，會走只測試裁切的快速路徑。
  • 每格都整個重畫的動畫，可以傳入 { preserveDrawingBuffer: false }。
  • 避免在動畫迴圈中呼叫 getImageData。
  • 不同的 WebGL context 之間無法共用紋理，所以 drawImage(另一個 context)、canvas 和影片每次呼叫都會複製一次畫面。內容不再變動的圖層，可以先用 await createImageBitmap(ctx2.canvas) 轉成 ImageBitmap，WebGL2D 會快取它的紋理。
  • imageSmoothingQuality 為 medium/high 且大幅縮小時，每個像素最多會取樣 64（medium）或 144（high）次。大量縮圖可以先縮到合適的尺寸並快取，或改用 low。
  • 內容相同的文字會命中遮罩快取；每格都變動的文字需要每次重新點陣化。
  • source-in、copy 等無界合成運算，每次繪製會多兩次全畫面 pass。
  • 混合模式（screen 除外）每次繪製都要經過離屏圖層，並複製一次目的地區域（只限圖形範圍）。大量小圖形使用相同的混合模式時，可以先畫到另一個 canvas，再用 drawImage 一次混合。
